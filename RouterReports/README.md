# RouterReports

Session report viewer for RouterRS (`../RouterRS`). Plain Node.js + Express,
no build step, no external CDN — works offline on installation machines.

```
npm install        # express only
node server.js     # http://localhost:8090, reads ../RouterRS/reports
node server.js --reports <dir> --port <port>
node --test        # reducer contract tests against shared fixtures
```

## What it shows

- **Session browser**: all sessions in the reports directory with size,
  duration, clean/crash exit, and fault counts.
- **Dashboard** per session: totals tiles, an installation-shaped unit
  health heatmap (state / ack % / timeouts / error logs; click a cell to
  jump to its events), traffic-and-faults timeline with operator markers,
  per-column connection table with latency percentiles, top-offender lists
  (worst ACK, most timeouts, noisiest loggers, rebooters), and the merged
  fault timeline.
- **Explorer**: filterable raw event stream (type / column / portal / log
  level), served incrementally — large NDJSON files are never buffered.
- **Export**: a self-contained static HTML report (summary + charts
  inlined) for emailing.

## Data contract

Events follow `../RouterRS/docs/report-schema.md` (v1). The NDJSON stream
is the source of truth: if a session has no `.summary.json` (crash) or a
stale one, `lib/reduce.js` regenerates it on the fly — `test/reduce.test.js`
asserts the Node reducer agrees with the Rust-generated summary on shared
fixtures (generated by `router-headless --simulate` with injected faults).
